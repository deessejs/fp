feat(web): integrate shadcn/ui with the fumadocs-ui theme

Wires shadcn/ui's design-token layer and component primitives into `apps/web` so that components added with `pnpm dlx shadcn@latest add <name>` render consistently with the existing fumadocs-ui marketing surface.

**What changed**

- `apps/web/src/app/global.css`
  - Adds the official fumadocs-ui shadcn interop import: `@import 'fumadocs-ui/css/shadcn.css';` alongside `lib/base.css`, `generated/shared.css`, and the four per-layout `generated/{home,docs,notebook,flux}.css` files. The shadcn CSS variables defined in `:root` and `.dark` now drive both `--color-fd-*` (fumadocs) and `--color-*` (Tailwind v4) tokens through the aliasing layer. The per-layout generated files are bags of `@source inline(...)` directives that register the class names `HomeLayout` / `DocsLayout` / `NotebookLayout` / `FluxLayout` reference (grid-cols-2/3/6, h-14, fd-layout, fd-sidebar, fd-toc, …) with the Tailwind JIT — without them, the JIT tree-shakes those class names out of the bundle and the pages render with HTML class names that have no CSS.
  - Adds the canonical shadcn `.dark` block (was previously only `:root`).
  - Replaces the inline comment that said "shadcn CSS variables were inlined because there is no `shadcn/tailwind.css`" with a comment that documents the actual loading path and explains why we skip `fumadocs-ui/css/preset.css` — its transitive `@import 'lib/shiki.css'` uses `@apply bg-fd-diff-remove`, a utility that this Tailwind v4 build does not define, and breaking the build on every page load. The shadcn preset does not use fumadocs' code-block styling, so dropping shiki.css is safe for the marketing surface. The four per-layout `generated/*.css` files are imported individually to recover the `@source inline` JIT hints that `preset.css` would otherwise pull in.

- `apps/web/components.json`
  - New file. Generated by hand to match the project layout (no `init` step ran because the shadcn CLI's auto-`npm install` step is broken in pnpm monorepos — see the PR description for the workaround). Aliases point at `@/components`, `@/components/ui`, `@/lib/cn`, and `@/hooks` so the CLI can later add components with `pnpm dlx shadcn@latest add <name>` from `apps/web` without interactive prompts.

- `apps/web/src/lib/cn.ts`
  - Switched from a one-line re-export of `twMerge` to the standard shadcn helper: `cn(...inputs) → twMerge(clsx(inputs))`. Required by every shadcn component for conditional class composition with conflict resolution. `clsx` is added as a runtime dependency.

- `apps/web/src/components/ui/button.tsx`, `apps/web/src/components/ui/card.tsx`
  - New files. Canonical shadcn "new-york" variants copied from the registry, with the `cn` import rewritten to the project's `@/lib/cn` alias. They are wired into the home page through the existing `CtaCard` component: the "Read the docs" link now uses `<Button asChild size="lg">`, the copy-to-clipboard npm command uses `<Button variant="outline" size="lg">`, and the surrounding container is `<Card>` + `<CardHeader>` / `<CardContent>` instead of hand-rolled `div`s. Type-check, lint, and the production build all pass.

- `apps/web/package.json`
  - Adds `class-variance-authority ^0.7.1`, `clsx ^2.1.1`, and `radix-ui ^1.7.0` as runtime dependencies. `radix-ui` is the new monorepo Radix package the latest shadcn components import from (it supersedes the per-primitive `@radix-ui/react-*` packages). No `@workspace/ui` package is introduced.

**What is intentionally not done**

- The PR does not run `npx shadcn-ui add` for every component the marketing site will eventually need. The Button and Card that ship here are the proof that the path works; further components can be added in their own commits with `pnpm dlx shadcn@latest add <name>` and they will land in the right place.
- The PR does not wire `next-themes` to a dark-mode toggle. The `.dark` CSS block is in place and is read by the existing shadcn `radix-ui` Slot + future components that respect `prefers-color-scheme`; surfacing a toggle is a separate concern.

**Caveats / known issues surfaced**

- The shadcn CLI was attempted first. Its auto-`npm install` step fails with `Cannot read properties of null (reading 'edgesOut')` in this pnpm monorepo. The CLI's own fallback message points to an older `shadcn@4.20.0`, which fails the same way. As a result, the components were written by hand from the canonical registry source (verified via `pnpm dlx shadcn@latest add --view`) and the dependencies were installed with pnpm. `components.json` is present so future `shadcn add` runs will resolve to the right paths.
- `fumadocs-ui/css/preset.css` is intentionally not imported (see the comment in `global.css`). The shiki.css path it pulls in is broken on Tailwind v4. If a future fumadocs-ui release fixes shiki.css, the import can be restored and the explicit `shadcn.css` + `lib/base.css` + `generated/shared.css` triplet collapses back to the documented two-line setup.
